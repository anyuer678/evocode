## 目标

项目详情页提供 **AI 医生**：基于分析产物的 RAG 问答，流式回复并附**可点击的代码引用**（文件/行号），支持文件预览（Monaco 按需加载）。交付物：AI 医生问答带引用，版本 v0.5。

## 交付

| 端 | 内容 |
|---|---|
| db | `V005__tech_doc.sql`（tech_debt / generated_doc，表结构先行，功能留 P7）＋ `V006__chat_rag.sql`（chat_session / chat_message / knowledge_chunk，knowledge_chunk 带 `vector(1024)` + HNSW 索引） |
| analyzer | 切片（tree-sitter 符号提取，≤800 token/块，超长 400/overlap 50 滑切）；`LLMClient.embed()`（OpenAI 兼容 `/embeddings`，模型默认 `bge-m3`）；PG 直连写/查 knowledge_chunk（随 analysis 全量重建）；`POST /analyze/v1/rag/index`、`POST /analyze/v1/rag/search`（向量 cosine top8 + 关键词 LIKE top4 合并去重 → topK=8）；`POST /analyze/v1/chat` SSE 生成端（delta/citations/done/error） |
| backend | chat_session / chat_message CRUD（V006 落库，含 citations jsonb）；`POST /api/v1/projects/{id}/chats/{id}/messages` → SSE 透传 analyzer（SseEmitter，不缓冲） |
| frontend | AI 医生对话页（会话列表 + 流式渲染 + 引用卡片 + Monaco 预览按需加载） |

## 关键决策（AD）

- **AD-P6-1 embedding 来源**：复用现有 `LLM_BASE_URL`/`LLM_API_KEY` 调 `/embeddings`，模型 `LLM_EMBEDDING_MODEL` 默认 `bge-m3`（1024 维，对齐 `vector(1024)`）。未配置 key → `embedding` 列留空，检索降级纯关键词（文件路径/符号 LIKE），配置好后再启用向量（与 LLM_NO_KEY 降级哲学一致）。
- **AD-P6-2 数据库边界**：analyzer 直连 PG（`ANALYZER_PG_DSN`，psycopg3），**只读写 knowledge_chunk 一张表**；切片+embedding+入库全在 analyzer（契约 §5.8 已定"直读磁盘不经 HTTP 传文件"），避免大 payload 往返。其余表仍归 backend。
- **AD-P6-3 切片单元**：复用 P4b 架构模块（`analyzer/app/core/arch/*.py`）的 tree-sitter 符号提取（函数/类/模块），`meta = {symbol, lang}`；超长函数 400 token 窗口滑切、overlap 50；`analysis_id` 随分析全量重建（07 字典定义）。
- **AD-P6-4 会话标题**：不额外发 LLM 请求，取首条 query 截断 ≤20 字作 title（规则版；AI 生成留待 P7 增强）。
- **AD-P6-5 引用防幻觉**：prompt 强约束只引用检索集合内文件（`[path:line]`）；输出后校验 citations ∈ 检索集合，否则剔除；检索为空 → 兜底话术"该问题超出当前分析范围，建议发起一次新分析"。
- **AD-P6-6 流式协议**：事件 `delta / citations / done / error`，协议与 06 §4 一致；backend→analyzer 同结构 SSE 透传不缓冲；history 截断 ≤6 轮 + 早期摘要。

## 风险与降级

- Docker/PG 不可用 → 无法真库验证，用单测 + mock 覆盖（沿用 P4/P5 惯例）
- embedding 网关无 bge-m3 → `LLM_EMBEDDING_MODEL` 覆盖为可用模型，维度变化时同步 `vector(n)`（迁移文件以 bge-m3 1024 为默认）
- LLM 无 key → chat 返回 error 事件带 LLM_NO_KEY 语义，前端提示配置；RAG 检索仍可用（关键词）
