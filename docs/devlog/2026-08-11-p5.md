## 关键决策

1. **非 Git 项目降级**：查询端点对非 Git 来源项目返回 **200 + `{available:false}`**（与 analyzer 05.6 契约一致，
   前端显示"非 Git 来源项目无演化数据"）。**偏离 06 §3.13 的 404/2001**（该错误码语义是"项目不存在"，用在
   "非 Git"上会造成前端无法区分"项目没了"与"没有 git 历史"）；沿用 P3a quality `available:false` 降级先例。
2. **热点双轨（规则先行，AI 可选）**：规则判定（按 commit_count / lines_added / 变更文件数阈值取 TOP-N，
   证据数组落库）→ 有 LLM key 时调 D.5 风险中心 Prompt 生成 `aiConclusion`（失败不阻塞，降级为规则结论）。
   复用 P2b 报告 LLM/RULES 双轨先例；hotspot.evidence 结构见 07 §5.6。
3. **git 统计实现**：subprocess 调系统 git（`git log --numstat --pretty=... --date=iso` 一次性取全量），
   **不引入 Python git 库**（保持 analyzer 依赖最小）；测试用临时 fixture git 仓库（本机 git 2.54 可用）。
4. **入库时机**：AnalysisRunner REPORT 阶段前调 `/analyze/v1/evolution`，按 analysis_id 落库
   commit_stat / file_change_stat / hotspot（失败降级：evolution 数据缺失不影响报告生成，同 P4b 架构降级）。
5. **不新增独立分析类型**：FULL 自动附带演化统计（与架构 P4b 一致）；`EVOLUTION` 类型枚举与单独触发留待后续。
6. **range 参数**：查询端点支持 `range=30d/90d/180d/all`（默认 30d），trend 按周聚合（契约 06 §3.13）。
