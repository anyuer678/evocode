## 联调发现并修复的 Bug

### 1. PG `TIMESTAMPTZ` ↔ `LocalDateTime` 映射错误（严重，破坏所有读写）

- **现象**：任何含时间字段的查询抛 `BadSqlGrammarException: Cannot convert TIMESTAMPTZ to LocalDateTime`，快扫直接 FAILED。H2 测试无法发现（H2 宽松）。
- **根因**：V001 迁移全部时间列用 `timestamptz`，但 entity/DTO 用 `LocalDateTime`（无时区），JDBC 类型不匹配。
- **修复**：9 个文件统一 `LocalDateTime` → `OffsetDateTime`（entity: Project/Analysis/FileNode；DTO: ProjectSummaryResp/ProjectResp/ProjectDetailResp/LatestAnalysisResp；config: MybatisPlusConfig 自动填充；service: QuickScanService）。JSON 输出变为带时区 ISO（如 `2026-08-10T17:00:33.3934344+08:00`），前端 `new Date()` 可正常解析。
- **规范沉淀**：**PG timestamptz 列 ↔ Java 一律用 OffsetDateTime**；新增时间字段沿用此约定。

### 2. 分页响应结构与契约不符

- **现象**：列表接口直接返回 MyBatis-Plus `IPage`，序列化为 `{records,total,size,current,pages}`，而契约 §1 规定 `{total,page,size,items}`——前端按契约解析会取不到 `items`。
- **修复**：新增 `common/PageResultResp<T>`（record + `of(IPage)`），ProjectController.list / FileController.list 统一转换。
- **注意**：泛型方法类型参数勿与 record 类型参数同名（javac 推断会出"推论变量不兼容"）；`Result.ok(PageResultResp.of(x))` 嵌套推断受限，用中间变量拆开。

### 3. analyzer lint 门禁回归

- 修复 `stackdetect.py` E501 超长行、`test_scan.py` F841 未用变量，`ruff format` 6 文件。

## 环境注意（本机）

1. **8080 端口冲突**：本机 Docker 常驻 `polycode-gateway` 占用 8080、`polycode-auth` 占用 8081。backend 需 `BACKEND_PORT=18080`（或停掉 polycode）启动；analyzer 8081 可侥幸绑定成功（127.0.0.1 优先）。项目默认配置不变，仅联调时覆盖。
2. **`mvnw spring-boot:run` 在本机中文路径（"烧token"）下报 `ClassNotFoundException`**：改用 `mvnw package -DskipTests` + `java -jar target/*.jar` 启动。
3. **curl 传 JSON**：PowerShell 单引号包裹的 `-d '{...}'` 会被 curl.exe 解析异常（HttpMessageNotReadable），用 `-d "@file.json"` 或 JSON 文件传参。
4. 三端测试命令的 "exit status 1" 为 PowerShell 管道误报（stderr 混入堆栈日志），`$LASTEXITCODE=0` 且 BUILD SUCCESS 即为通过。
