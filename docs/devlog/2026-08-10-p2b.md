## 交付内容

### analyzer（docs/06-API契约.md §5.2）

新增 4 个 core 模块 + 端点 + 测试：

- `core/report_rules.py`：规则版评分器。**健康分 = quality×40% + structure×30% + dependency×15% + scale×15%**（02 §10；v0.1 无 Sonar：quality 用扫描代理指标、dependency 给中性分），附加 `scoreDetail` 保证可解释、可复现；level 分档（≥90 EXCELLENT / ≥75 GOOD / ≥60 FAIR / POOR）；risks/recommendations 按扫描信号生成
- `core/llm.py`：**LLM Provider 抽象（AD-3 自写接口，不引 LangChain）**——`LLMClient` Protocol + `OpenAICompatClient`（OpenAI 兼容 /chat/completions，json_object 模式、超时、重试、容错 JSON 解析）；无 Key → `available()=False`
- `core/prompts.py`：`REPORT_PROMPT_VERSION = "report-1.0"`，system + user 模板（AD-12：只发结构化摘要，不发文件全文；历史仅带最近 3 期）
- `core/reportgen.py`：编排——规则版兜底 → LLM 尝试生成并校验（dimensions 恰好 4 项/顺序固定/类型检查）→ **失败降级 RULES（HTTP 仍 200，AD-9 永不卡死）**；LLM 修正被夹回基础分 ±10（AD-14）
- `main.py`：`POST /analyze/v1/report`
- `tests/test_report.py`（8 例）：规则版结构/大文件扣分/历史差分、LLM 版使用与 clamp、坏结构/异常/无 Key 降级、端点

### backend（docs/06-API契约.md §3.7）

- `AnalyzerClient.report()`：调 /analyze/v1/report，任何响应视为成功（analyzer 内部降级）
- `AnalysisRunner`：REPORT 阶段接入——SCAN_DONE(70) → REPORT(75→95) 调 report → 回填 `report_json`/`reportSource`/`promptVersion` → SUCCEEDED(DONE,100)；新增 `regenerateReport()`（不重扫，由 file_node 快照 + 项目档案重建 scan 摘要）
- `AnalysisService.report/regenerate` + `AnalysisController`：`GET /analyses/{id}/report`、`POST /analyses/{id}/report/regenerate`（前置 2001：分析不存在或无报告；排他 2008：RUNNING 期间再次触发）
- `FileNodeService.listAllForReport()`：最近成功快照全量文件
- 测试：Runner（报告回填/regenerate 覆盖+regeneratedAt）、Service（report 查询/缺失 2001/regenerate 排他 2008/触发）、Controller（report 载荷/regenerate 202）
