> 日期：2026-08-13 ｜ 提交：见 git log（commit message「feat: TD-05 Redis 列表读缓存——Spring Cache + 降级」） ｜ 状态：完成

## 背景

TD-05 记录 Redis 端口已预留（AD-017 解决端口冲突）但代码无任何使用，属「预留未用」工程债。台账 §5.3 给出两个方向：① 任务队列（替换内存 `@Async`）② 读缓存（file_node/列表页），均要求「出 AD-018」。

## 决策（AD-018）

**选读缓存，不选任务队列**：列表读缓存直接对应「列表接口 P95 <500ms」验收、只动读路径风险低；任务队列需替换 `AnalysisRunner` 内存状态机（AD-5）并发语义复杂，留待 A2 有真实并发压测数据后再评估。

## 实现

- **依赖/配置**：`pom.xml` 加 `spring-boot-starter-data-redis`；`application.yml` 加 `spring.data.redis`（`127.0.0.1:6380`，对齐 AD-017 端口改绑）
- **`CacheConfig.java`**（新增）：`@EnableCaching` + `RedisCacheManager`——`GenericJackson2JsonRedisSerializer`（注册 JavaTimeModule 支持 OffsetDateTime、NON_FINAL 类型信息保 `@class` 可反序列化）+ TTL 60s + 禁缓存 null；`CacheErrorHandler` 四个方法一律忽略缓存异常（降级直查库，延续 TD-08 降级对称原则）
- **`ProjectServiceImpl`**：`list` 加 `@Cacheable(cacheNames="projectList")`；`createFromZip`/`createFromGit`/`update`/`delete` 加 `@CacheEvict(allEntries=true)` 精确失效
- **单测**：`CacheConfigTest` 2 例（cacheManager 构建、errorHandler 吞异常）

## 边界 / 遗留

- 分析完成引起的 `healthScore`/`lastAnalyzedAt` 变化由 60s TTL 兜底（Dashboard 场景 1 分钟延迟可接受，AD-018 已记录）；如需即时刷新可后续在 AnalysisRunner 分析完成点手动 `CacheManager.evict`。
