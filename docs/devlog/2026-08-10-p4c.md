> 2026-08-11 · 阶段目标记录（实施前起草，实施后补全交付/验证）

## 目标

P4a 产出 analyzer `/analyze/v1/architecture`，P4b 落库 V003 + `GET /projects/{id}/architecture`（2010 无数据 404）。
P4c 是 P4 的最后一块：**前端消费架构接口，呈现可视化架构视图**，补上 P4 阶段"能看"的能力。

范围：仅在项目详情页新增"架构分析"区块，不改动后端、不改动 analyzer。

## 关键决策

1. **图库选 ECharts**：README 架构图早已声称 `Vue3 + Vite + ECharts`，P7 Dashboard 也要用；graph 系列支持分层定位（`layout: none` + 手算层级 y），契合 LAYER_VIOLATION 语义。不引入 antv G6 / vis-network，控制依赖面。
2. **布局 = 分层**：按 `nodeType`（CONTROLLER/SERVICE/REPOSITORY/ENTITY/UTIL/OTHER）分泳道排布，y 轴分层、x 轴组内展开；违规边标红、可点选高亮对应节点。
3. **空态/错误态**：404(2010) → "尚无架构分析，先发起 FULL 分析"；空数据同；加载中转圈；失败提示可重试。与质量区/报告区一致的交互风格。
4. **analysisId 跟随**：默认取最新（不传参），复用详情页已有的 analysis 历史选择器思路；本轮不单独做多版本切换（留待演化阶段），保持最小闭环。
5. **metrics 展示**：节点 hover 显示出入度（outDegree/inDegree）。

## 踩坑（实施后补）

1. **`architecture.ts` 双前缀 bug**：URL 写成 `/api/v1/projects/{id}/architecture`，而 axios `baseURL` 已是 `/api/v1`，实际请求变成 `/api/v1/api/v1/...` → 后端必 404/500。修复：URL 只写 `/projects/...`，与其他 api 模块一致。
2. **字符串模板 ref 不回填 `.value`**：`<div ref="chartEl">` + `<script setup>` 的 `const chartEl = ref(null)` 编译后 `ref` 只写入 `instance.refs`，`chartEl.value` 始终为 null → `render()` 首行静默 return，ECharts canvas 永不创建（violations 列表正常，极具迷惑性）。修复：改用回调 ref `:ref="setChartEl"`。
3. **`nextTick` 在异步 ref 回填前提前 resolve**：`arch.value = data` 后 `await nextTick()`，实测 setChartEl 在 nextTick 之后才被调用，render 拿到的仍是 null。修复：改用 `watch(() => arch.value, render, { flush: 'post' })` 驱动渲染。
4. **非 2xx 响应丢失业务 code**：后端 2010 返回 HTTP 404，axios 走响应拦截器 error 回调（不经过 success 分支），`err.code` 从未被附上 → 空态误判为 error（显示 "Request failed with status code 404"）。修复：error 回调里从 `error.response.data.code` 回填 `err.code`。
