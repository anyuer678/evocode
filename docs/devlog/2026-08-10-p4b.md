## 关键决策

1. **架构结果以 analysisId 为单位隔离**（质量 issue 是全项目替换）。同分析重跑先删后插幂等；
   查询 `analysisId` 缺省时直接按 `architecture_node.project_id` 取最新一条（绕开 analysis 状态，
   最近一次分析失败时仍可读上次架构结果）。
2. **节点先落库拿自增 id，边/违规再以 nodeKey 映射**为 source/targetNodeId；引用未知节点的边
   跳过并记 WARN，避免脏数据。
3. **架构失败只降级不阻塞**：`runArchitecture` 包 try/catch，analyzer 不可达时跳过落库，报告照常
   生成（与质量降级一致）。前端此时取架构得 404/2010。
4. `AnalysisRunner` 构造器 5→6 参（注入 ArchitectureService），FULL 时序变为：
   `scan → SCAN_DONE(70) → runQuality → runArchitecture → generateAndStoreReport → DONE(100)`。

## 踩坑

1. **PowerShell → curl.exe 的引号转义**：`curl -d '{"type":"FULL"}'` 的引号会被
   MSVC argv 解析吞掉，Jackson 报 `Unexpected character 't'`。解法：body 写入临时文件，
   `curl --data "@body.json"`。
2. **端口**：backend 默认 8080 与 polycode-gateway 冲突，需 `BACKEND_PORT=18080`；
   analyzer 默认 8000，但 backend `analyzer-url` 默认 `http://127.0.0.1:8081`，
   联调时 analyzer 必须起在 8081。
3. **MyBatis-Plus 3.5.7 `insert` 重载**：`BaseMapper` 新增 `insert(Collection<T>)`，Mockito
   `verify(...).insert(any(ArchitectureNode.class))` 触发重载歧义，需显式 cast。
4. **Windows 下 PowerShell `Set-Content -Encoding UTF8` 写 BOM**，javac 报 `\ufeff` 非法字符，
   用 python 去 BOM。
5. `LambdaQueryWrapper<>()` 在链式 `.eq(方法引用)` 时 diamond 推断失败，统一显式泛型。
