## P9a UI 精致化

### 目标
保留现有卡片/区块信息架构，消除"单调"：视觉层次、列表可扫读性、状态反馈。

### A1. 设计 token 精修（styles/variables.css）

| Token | 现值 | 目标 | 理由 |
|---|---|---|---|
| `--font-family` | 浏览器默认 | `system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` | 明确字体栈，跨平台稳定 |
| 数字/度量 | 继承 | 卡片内数字加 `font-variant-numeric: tabular-nums`；`.stat-num`/健康分等用 | 数字对齐防跳动 |
| `--radius-*` | 6/8/10 | 6/10/12（卡片/弹窗加大） | 卡片更圆润现代 |
| 阴影 | 1 级 | **3 级**：`--shadow-xs`（hover 卡片）/`--shadow-md`（卡片默认）/`--shadow-lg`（弹窗/浮层） | 层次感 |
| 间距 | 零散 | 4pt 体系：`--space-1..6` = 4/8/12/16/24/32；区块统一 `margin: var(--space-5)` | 对齐 |
| 焦点 | 无 | 全局 `:focus-visible { outline: 2px solid var(--primary-weak); }` | 可访问性 |
| 过渡 | 无 | 统一 `--transition: 150ms ease`（按钮/卡片 hover/主题切换） | 手感 |

### A2. 项目列表卡片化（project-list/index.vue）

**布局**：默认**卡片网格**（`grid-template-columns: repeat(auto-fill, minmax(300px, 1fr))`），保留右上角"列表/卡片"视图切换（localStorage 记忆）。

**卡片结构**（自上而下）：

- 语言徽章：langStats 占比 top2 渲染为小徽章（`Java 61%`），颜色取**固定语言色板**（Java 橙/JS 黄/Python 蓝/Go 青…，深色下用弱化变体）

- 状态▾：全部/READY/ANALYZING/FAILED/CREATED

### A3. 空态 / 骨架 / 动效

## P9b 项目操作与报告导出

### B1. 接口契约

**PATCH `/api/v1/projects/{id}`**（重命名/改描述）
```jsonc
// req: { "name": "新名称", "description": "新描述" }   // 均可选，至少一个
// 200: { "code": 0, "data": { "id": 13, "name": "新名称", "description": "…", "status": "READY" } }
// 400: 1001 参数缺失 / 1002 name 长度超限（≤100）
// 404: 2001 项目不存在
```
- 校验：name 非空且 ≤100；description ≤500；`status = CREATED/FAILED` 也允许改名（只改元数据不动状态）

**GET `/api/v1/projects/{id}/report/export`**（最新报告导出 Markdown）
```jsonc
// 响应: 200 text/markdown; charset=utf-8
//       Content-Disposition: attachment; filename="evocode-{projectId}-report-{analysisId}.md"
// 404: 2001 项目不存在 / 报告不存在（无 SUCCEEDED analysis）
```

### B2. Markdown 模板（backend 生成，从 report_json 映射）

```markdown
# {projectName} 体检报告

> 分析时间：{finishedAt} ｜ 健康分：**{healthScore}**（{level}）｜ 来源：{LLM/RULES}

## 概览
| 维度 | 分数 | 星级 | 摘要 |
|---|---|---|---|
| 质量 | 70 | ★★★★ | … |

## 风险与建议
| 等级 | 标题 | 说明 | 建议 |
|---|---|---|---|
| HIGH | … | … | … |

## 分阶段建议
- 第一阶段：…
```
- 映射：`report.dimensions` → 概览表；`report.risks` → 风险表（无则"无重大风险"）；`report.recommendations` → 列表
- 实现：backend 新增 `ReportExportService`（纯字符串拼接，无第三方 markdown 库），注入 ProjectMapper/AnalysisMapper
- 复用：详情页报告 JSON 已在前端渲染，导出为服务端文本（浏览器 `<a download>` 触发）

### B3. 前端交互

- 卡片/详情页"操作"菜单（`⋮` → 重命名 / 导出报告 / 删除）
- 重命名弹窗：name/description 两字段，提交 PATCH，成功后刷新列表（Toast 提示）
- 导出：`window.open('/api/v1/projects/{id}/report/export')` 或 `<a href>`（下载头触发）；无报告时 Toast 提示"暂无报告"
- 删除确认：现有 confirm 升级为弹窗（输入项目名确认），错误 2001 提示

## P9c 历史报告对比

### C1. 接口契约

**GET `/api/v1/projects/{id}/report/history?limit=10`**
```jsonc
// 200: { "code": 0, "data": { "items": [
//   { "analysisId": 27, "createdAt": "…", "healthScore": 82, "level": "GOOD",
//     "dimensions": [ { "key": "quality", "score": 70, "stars": 4 }, … ],
//     "source": "RULES" } , … ] } }
// 404: 2001 项目不存在；无 SUCCEEDED 分析 → items: []
```
- 实现：AnalysisMapper 查 `project_id + status='SUCCEEDED' + report_json IS NOT NULL`，`ORDER BY id DESC LIMIT ?`（默认 10，上限 20），映射 healthScore/level/dimensions 摘要
- 复用 healthScore 数值防御（同 P8 列表 SQL 的 CASE WHEN）

### C2. 前端交互（详情页报告区块）

- 报告区顶部加 **"历史趋势"折叠区**（默认收起，`▶ 历史趋势 (N 期)`）：
  - **健康分趋势折线**：ECharts `line`，x=分析日期，y=healthScore，`≥80/≥60` 参考线着色，点 hover 显示维度
  - **最近两期对比**：维度分组条形（两期并排，差值为正绿/负红标注）；风险 diff 列表——新增风险（第二期有第一期无）标红、已消失标绿、持续标黄
- 数据：`report/history` 一次拉取，前端本地算 diff
- 交互：折线点点击 → 切换"对比基准"为该期（默认最新两期）

## P9d 依赖分析可视化

### D1. analyzer `/analyze/v1/dependency`

```jsonc
// req: { "projectId": 1, "codeDir": "data/projects/1" }
// 200: { "available": true, "dependencies": [
//   { "name": "org.springframework.boot:spring-boot-starter-web", "version": "2.5.14",
//     "type": "MAVEN", "file": "pom.xml",
//     "risk": "HIGH", "reason": "Spring Boot 2.5 已 EOL（2023-11 结束支持）", "latest": "3.x" }, … ] }
// 非 Maven/npm 项目或无可解析依赖 → { "available": false, "dependencies": [] }
```
- **解析**（纯文本/正则，不引第三方）：
  - `pom.xml`：`<groupId>/<artifactId>/<version>` 从 `<dependency>` 块提取（正则跨行 `<dependency>[\s\S]*?</dependency>`），只取直接依赖；parent 的 `<version>` 记 project 版本
  - `package.json`：`dependencies`/`devDependencies` 对象（JSON 解析）
  - 支持语言文件缺失 → available=false
- **EOL 规则表**（内置常量，`dep_eol_rules.py`）：Spring Boot `2.5.x→EOL(HIGH, latest 3.2+)`、`2.6/2.7→EOL`、Vue2 `2.x→EOL`、`react 16/17→EOL`、`node <18→EOL`、`python 3.7-→EOL`；未命中规则 → `risk: null`（前端显示"未知版本，建议人工确认"）。规则表可扩展（字典驱动）
- 主版本降级：解析版本 `2.5.14` → major `2` + 规则匹配前缀

### D2. 落库（复用 V002 dependency 表）

核对 `db/migration/V002__quality_issue.sql` 是否含 dependency 表（07 字典 §3.4 有定义：project_id/analysis_id/name/version/type/file/risk_level…）。若 V002 缺该表 → 新增 `V009__dependency.sql`（按 07 §3.4 字段建表 + 索引）。

- AnalysisRunner 加 `runDependency`：调 analyzer → `dependencyMapper.replaceForAnalysis`（同 analysis 先删后插，available=false 时清空该项目——与 evolution 同语义）
- 失败降级：不阻塞分析（catch 记录），报告/技术债 DEPEND 源**改为读 dependency 表**（替代 P7 从 report_json.risks 提取的临时方案）

### D3. 前端依赖区块（详情页）

- 位置：质量区块后
- 内容：风险分组（HIGH/中/低/未知）+ 依赖表（名称/版本/风险徽标/reason/latest）；顶部统计卡（总依赖/EOL 数/高风险数）
- 空态：无依赖文件 → "未检测到 Maven/npm 依赖"；available=false → 同文案
- 徽标色：HIGH=--fail-weak/color、EOL=--warn-weak、未知=--bg-muted

## P9e 进度通知与搜索增强

### E1. 分析进度 SSE

**GET `/api/v1/projects/{id}/analyses/events`**
```
// 200 text/event-stream（复用 §4 SSE 帧格式）
event: analysis-progress
data: {"analysisId": 26, "status": "RUNNING", "stage": "SCAN", "progress": 30, "message": "扫描中…"}

event: analysis-progress
data: {"analysisId": 26, "status": "SUCCEEDED", "stage": "DONE", "progress": 100, "message": "分析完成"}
```
- 触发：AnalysisRunner 状态机变更点（QUEUED→RUNNING/SCAN_DONE/REPORT→SUCCEEDED/FAILED）调 `AnalysisProgressPublisher.publish(projectId, analysisId, status, stage, progress)`
- 实现：`AnalysisProgressPublisher`（@Component，`Map<Long, SseEmitter>` 按 projectId 注册，publish 遍历 send；超时/断开清理）——复用 chatExecutor 线程池 + SseEmitter 模式；**断线不重放历史**（前端另用现有轮询接口补状态）
- 前端：详情页分析中建立 `EventSource('/api/v1/projects/{id}/analyses/events')`，onmessage 更新进度条/阶段标签；`SUCCEEDED/FAILED` → Toast 提示 + 刷新数据；页面离开 close()
- 降级：EventSource 失败/断线 → 回到现有轮询（analysis 状态接口已有）

## 边界与风险

| 项 | 说明 |
|---|---|
| 报告导出大 JSON | report_json 最大 ~几百 KB，markdown 化可控；导出时截断超长字段（风险 detail ≤500 字） |
| 依赖 EOL 表覆盖 | 内置规则覆盖主流；未命中 → risk:null 不误报；规则表常量集中，易扩展 |
| 进度 SSE 多端 | 单用户本地部署（v1.0 无鉴权）——按 projectId 广播；多标签页各自订阅无冲突 |
| 历史对比数据量 | limit ≤20 期；维度 diff 只算最近两期 |
| P9a 列表语言选项 | 依赖当前页项目聚合（size=100 上限）；项目超 100 时语言选项可能不全（沿用现有上限，devlog 记录） |
