## 交付内容（docs/06-API契约.md §3.5/3.6）

新增：

- `controller/AnalysisController`：
  - `POST /api/v1/projects/{id}/analyses` → 202（body `{"type":"FULL"}`；v0.1 仅 FULL，其他 1002）
  - `GET /api/v1/projects/{id}/analyses` → 分页历史（按 id 倒序）
  - `GET /api/v1/analyses/{id}` → 状态轮询（2s 间隔）
- `service/analysis/AnalysisService` + `AnalysisServiceImpl`：
  - create：项目校验（2001）→ 类型校验（1002）→ **排他**（存在 PENDING/RUNNING 的 FULL → 2002）→ 落 PENDING(QUEUED,0) → 异步执行
  - history/status：错误码与分页参数校验（1003）
- `service/analysis/AnalysisRunner`（独立 bean，`@Async("quickScanExecutor")` 跨 bean 调用生效）：
  - 状态机：PENDING(QUEUED,0) → RUNNING(SCAN,5) → SCAN_DONE(70) → SUCCEEDED(DONE,100)
  - 复用 analyzer `/analyze/scan` + `FileNodeService.replaceSnapshot` + 项目档案回填（与 QuickScanService 语义一致）
  - 取消检查（CANCELLED 中止）、失败 → FAILED + project FAILED、项目已删 → FAILED
  - **REPORT 阶段为占位**（P2b 接入 analyzer `/analyze/report` 后回填 report_json / reportSource / healthScore）
- `dto/analysis/`：`AnalysisResp`（202）、`AnalysisHistoryResp`（含 source/healthScore）、`AnalysisStatusResp`、`AnalysisCreateReq`
- 测试：`AnalysisServiceTest`（7 例：排他/类型/轮询/错误码）、`AnalysisRunnerTest`（4 例：状态机/失败/取消/项目删除）、`AnalysisControllerTest`（5 例：202/2002/1003/轮询）

## 实库联调验证

- 创建 zip 项目 → 自动快扫（type=FULL, SUCCEEDED/SCAN_DONE/70）
- 显式发起 FULL 分析 → 202 PENDING/QUEUED/0 → 轮询至 SUCCEEDED/DONE/100
- 历史两条（FULL DONE 100 + 快扫 SCAN_DONE 70），`{total,page,size,items}` 分页格式正确
- 错误场景：不存在的分析 2001、非法类型 1002、不存在的项目 2001
- 排他 2002 由单元测试覆盖（异步任务 <1s，实库难以稳定复现）

## 踩坑记录

1. **MyBatis-Plus `Page.convert` 返回 `IPage<R>`** 而非 `Page<R>`——接收变量必须声明为 `IPage<R>`（FileController 已是此写法，AnalysisServiceImpl 首次误写 `Page<R>` 导致 javac 泛型不兼容）。
2. **mock `insert` 不回填自增 id**——`analysis.getId()` 为 null，`verify(runner).run(10L)` 断言失败；用 `thenAnswer` 显式回填。
3. `anyString()` 不匹配 null：controller 缺省 body 场景用 `Mockito.isNull()`。
